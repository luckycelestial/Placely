# My Applications

## Purpose
The My Applications screen is where students track every drive they have applied to and follow the status of each one through the placement process.

## User role
- Student only.

## Navigation placement
- Student desktop shell uses sidebar navigation.
- Student mobile shell uses bottom navigation.
- This is a core tracking screen in the student shell.

## Screen goal
This screen should make each application feel like an active workflow object, not just a passive record. Students should immediately see status, deadlines, pending actions, and next steps.

## Core sections
- Application summary cards.
- Status filters.
- Deadline reminders.
- Pending action alerts.
- Application timeline or history view.
- Next-step CTA for each application.

## Key actions
- Open application details.
- Filter applications by status.
- Review pending tasks.
- Check deadlines and interview stages.
- Jump to next required action.
- Track changes in application progress.

## Content rules
- Show status clearly on each application.
- Surface what the student must do next.
- Make expired, rejected, shortlisted, selected, and waiting states visually distinct.
- Keep the timeline readable and useful.

## States
- No applications yet.
- Active applications in progress.
- Shortlisted or interview stage.
- Selected or offer-linked application.
- Rejected or closed application.

## Data needed
- Company name.
- Role title.
- Applied date.
- Current status.
- Timeline events.
- Deadline or next interview date.
- Pending requirements.
- Final outcome.

## UX notes
- Use cards plus a timeline or drilldown pattern.
- Keep the most important next action visible.
- Avoid flattening the workflow into a simple list.
- Make history and status progression easy to understand.

## Related screens
- Student Dashboard.
- Job Opportunities / Drives.
- My Progress / ATS Timeline.
- Offers & Joining.
- Notifications / Task Inbox.
