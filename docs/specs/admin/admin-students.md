# Students

## Purpose
The Students screen is the admin workspace for viewing, filtering, reviewing, and managing student records across the college.

## User role
- Placement Staff.
- Placement Admin.
- College Super Admin.

## Navigation placement
- Admin desktop shell uses a right-side sidebar.
- Admin mobile shell uses bottom navigation or drawer behavior where needed.
- This is one of the main operational list screens in the admin shell.

## Screen goal
This screen should make it easy for admins to find a student, understand their placement readiness, and open the right student record or filter view without friction.

## Core sections
- Search bar.
- Advanced filters.
- Student list or table.
- Profile completeness indicator.
- Eligibility or status badges.
- Verification markers.
- Bulk action controls.
- Student detail panel or drilldown.

## Key actions
- Search students by name, register number, department, year, or skill.
- Filter students by CGPA, backlog, eligibility, profile status, and placement status.
- Open a student record.
- Review verification or missing data.
- Apply bulk actions where permitted.
- Jump from a student row to related applications or documents.

## Content rules
- Keep the table dense but readable.
- Make filters strong enough for real placement operations.
- Show the most useful placement indicators first.
- Support saved views or recurring operational filters.

## States
- No matching students.
- Filtered list with a small segment.
- Large department or year-wide list.
- Student needing verification or correction.
- Bulk review mode.

## Data needed
- Student name.
- Register number.
- Department.
- Year.
- CGPA.
- Placement status.
- Profile completeness.
- Verification state.
- Eligible or blocked state.

## UX notes
- Use quick filters and advanced filters together.
- Let admins move from list to student details quickly.
- Support export or bulk review where relevant.
- Avoid hiding important placement signals behind extra clicks.

- Offers & Joinees.
