# Applications

## Purpose
The Applications screen is the admin workspace for reviewing, filtering, and managing student applications across drives.

## User role
- Placement Staff.
- Placement Admin.
- College Super Admin.

## Navigation placement
- Admin desktop shell uses a right-side sidebar.
- Admin mobile shell uses bottom navigation or drawer behavior where needed.
- This is a key workflow screen in the admin shell.

## Screen goal
This screen should give admins a clear view of all applications, their current status, and the next operational step for each one.

## Core sections
- Application list or table.
- Status filters.
- Drive filters.
- Student and company search.
- Shortlist or review actions.
- Application detail panel.
- Timeline or stage summary.

## Key actions
- Search applications.
- Filter by status, drive, department, or year.
- Open a specific application.
- Shortlist, reject, or move an application forward.
- Review pending actions.
- Jump into ATS detail when needed.

## Content rules
- Keep the workflow status visible.
- Show the next action clearly.
- Make it easy to move between application, ATS, and offer stages.
- Support power-user filtering.

## States
- No applications yet.
- Large active queue.
- Shortlist review state.
- Interview stage state.
- Final outcome state.

## Data needed
- Student name.
- Drive name.
- Company name.
- Role title.
- Application date.
- Current status.
- Interview or shortlist stage.
- Final result.

## UX notes
- Use clear filters and compact tables.
- Make drilldown into ATS simple.
- Keep high-volume workflows fast.
- Avoid forcing staff to jump across unrelated screens.
