# Settings

## Purpose
The Settings screen is where admins manage tenant configuration, roles, policies, branding, notifications, and system preferences.

## User role
- Placement Admin.
- College Super Admin.
- Placement Staff for limited preference settings where allowed.

## Navigation placement
- Admin desktop shell uses a right-side sidebar.
- Admin mobile shell uses bottom navigation or drawer behavior where needed.
- This is the control-center settings screen in the admin shell.

## Screen goal
This screen should let the college configure how CareerBridge behaves for their institution without needing code changes for every operational rule.

## Core sections
- Role and permission settings.
- College branding settings.
- Notification preferences.
- Placement policy settings.
- Department or year-specific controls.
- Document and profile rules.
- Tenant configuration.
- Integration or system settings.

## Key actions
- Update branding and college identity.
- Manage user roles and permissions.
- Adjust placement rules or thresholds.
- Configure notifications or templates.
- Set required profile and document fields.
- Save system-wide preferences.

## Content rules
- Keep permissions and sensitive settings clear.
- Separate policy, branding, and integrations into organized groups.
- Make it obvious which settings apply to the whole college and which apply to a subset.
- Avoid mixing operational controls with cosmetic preferences.

## States
- Default settings.
- Partially configured tenant.
- Saved but not yet published where relevant.
- Restricted admin-only controls.
- Validation error state.

## Data needed
- College name and branding assets.
- Role definitions.
- Policy thresholds.
- Notification templates.
- Document rules.
- Integration flags.
- Tenant identifiers.

## UX notes
- Use grouped sections or tabs.
- Make sensitive actions deliberate and traceable.
- Keep the most important rules easy to find.
- Support preview or validation before saving when needed.
